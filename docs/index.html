2. 핵심 항등식 (근사 없음)

연초 인출 구조 $A_{t+1} = (A_t - C_t)(1+R_t)$ 를 누적수익 G_t = \prod_{s<t}(1+R_s) 로 디플레이트하면 정확히

A_n / G_n = A_0 - \sum_{t=0}^{n-1} \frac{C_t}{G_t}

즉 n년 시점 고갈 ⟺ S_n \equiv \sum_{t<n} C_t/G_t \geq 25. $S_n$은 단조증가라 최초통과시점이 곧 고갈 시점입니다. 30년 전체:

  • $E[S_{30}] = 29.02$억, \mathrm{SD}(S_{30}) = 10.18억 (적률은 정확히 계산 가능)
  • $E[S] = 29.0 > 25$ — 인출 스트림의 실효 현가가 이미 원금을 넘습니다

7. 가정과 한계

  • 수익률 iid 로그정규, 물가 2% 결정론적, 연초 인출, 세금·수수료·사망률·연금소득 없음
  • 항등식(§2)과 $S_n$의 1·2차 적률은 정확. 근사는 (a) $S_n$의 로그정규 근사, (b) \ln S–$Y$ 이변량 정규 근사 두 곳뿐이며, 임계값 25가 $S$의 중앙값 근처라 근사가 잘 듣는 영역입니다. 다만 시점 분포의 양 끝(12년 이전, 29~30년차)은 오차가 상대적으로 큽니다.
  • iid 가정은 평균회귀를 무시하므로 실제 시장 대비 고갈 확률을 다소 과대 추정하는 경향이 있습니다.

검증용 스크립트

import numpy as np
rng = np.random.default_rng(0)
N, T = 200_000, 30
mu_r, sig = 1.055/1.02 - 1, 0.12          # 실질 산술평균, 변동성
s = np.sqrt(np.log(1 + sig**2/(1+mu_r)**2))
m = np.log(1+mu_r) - s**2/2
R = np.exp(rng.normal(m, s, (N, T)))       # 실질 총수익 팩터
C = 1.2 * (1.025/1.02)**np.arange(T)       # 실질 인출액

A = np.full(N, 25.0); ruin_yr = np.full(N, -1)
for t in range(T):
    dead = (ruin_yr >= 0) | (A < C[t])
    ruin_yr[dead & (ruin_yr < 0)] = t
    A = np.where(ruin_yr >= 0, 0.0, (A - C[t]) * R[:, t])

failed = ruin_yr >= 0
g5 = R[:, :5].prod(1)**(1/5) - 1
print(f"고갈확률 {failed.mean():.1%}  중앙 고갈연차 {np.median(ruin_yr[failed]):.0f}")
print(f"초기5년 실질(연율)  고갈 {g5[failed].mean():.2%} / 생존 {g5[~failed].mean():.2%}")

06 · FAQ

의심스러운 것들

내 숫자는 어디로 가나?

원격 MCP fintool-mcp.risingdream.workers.dev는 Cloudflare Worker가 요청을 받아 컨테이너 안의 fintool 바이너리가 계산한다. D1에 남는 것은 OAuth 클라이언트·토큰 상태뿐이고, 계산 입력과 결과는 저장하지 않는다. 로컬에서 돌리고 싶으면 같은 바이너리를 fintool mcp로 직접 띄울 수 있다.

엔진이 갱신되면 다시 설치해야 하나?

아니다. 계산 도구는 서버 재배포로 갱신되고 플러그인 재설치가 없다. 스킬 문서가 바뀔 때만 plugin.json 버전이 올라가고, 마켓플레이스 갱신으로 받는다.

엑셀 함수와 같은 값이 나오나?

amort는 IPMT/PPMT/CUMIPMT/CUMPRINC/ISPMT, bond는 PRICE/YIELD/DURATION과 같은 규약을 쓴다. 예: 3억·연 4.5%·30년 원리금균등의 2년차 이자 13,178,657은 CUMIPMT(0.045/12, 360, 300000000, 13, 24, 0)과 같은 값이다.

Before 쪽도 꽤 잘 답하던데?

맞다. 과장하지 않았다. 이 모델은 전환사채도 손으로 맞춘다. 차이는 "틀린다"가 아니라 "검증할 수 없다"와 "비용"에 있다. 없음 열은 근거가 본문뿐이고 출력이 2~3배 길다. fintool 열은 호출 인자와 봉투가 남아 같은 입력으로 누구나 다시 돌릴 수 있고, 가정을 쓸 때는 첫 줄에 밝히고 민감도를 같이 낸다(사례 C).
