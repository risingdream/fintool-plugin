01 · BEFORE / AFTER

같은 프롬프트, 플러그인 없이 / 있이

2026-08-23 Claude Code에서 같은 모델·같은 프롬프트를 플러그인 off/on으로 실제 실행한 기록이다. 두 열 모두 응답을 고치지 않았고, "없음" 쪽은 셸·파일 도구 없이(Claude Desktop의 일반 채팅과 같은 조건) 돌렸다. 각 열 아래 원문 링크로 도구 호출·반환까지 전부 볼 수 있다.

런웨이 · 자금소요

본질 · 재현성
프롬프트월 매출 3천만 원, 월 30% 성장, 고정비 8천만 원, 현금 6억. 런웨이와 다음 라운드 필요액은?

  • 고정비 8천만 원은 유지(인원 증원 없음)

결론

  • 런웨이: 사실상 무한. 30% 성장이 유지되면 5개월 차에 손익분기 도달, 누적 번은 약 1.34억에 그치고 현금 최저점은 약 4.66억입니다.
  • 다음 라운드 필요액: 생존 목적으로는 0원. 현금이 1.3억만 소요되는 계획에 6억이 있으니 생존용 펀딩은 불필요합니다. 조달이 필요하다면 "생존"이 아니라 "성장 가속(채용·마케팅 투자)" 명분이어야 하고, 그 필요액은 투자 계획에 따라 정해지는 것이지 이 숫자에서 도출되지 않습니다.

진짜 리스크는 성장률 가정

월 30%를 1년 이상 유지하는 회사는 거의 없습니다. 성장률이 꺾일 때의 그림:

10%12개월3.2억무한(최저 현금 2.8억)

매출총이익률이 70%라면 30% 성장에서도 손익분기는 6개월, 누적 번 약 2.1억으로 늘어나지만 여전히 안전합니다.

실무 권장

  • 성장률이 월 10% 이하로 떨어지는 것이 관측되면 즉시 라운드 준비를 시작하세요. 런웨이 12개월 지점(성장 0% 기준)이 마지노선이고, 펀드레이징에 보통 6개월이 걸리므로 6개월 전에는 움직여야 합니다.
  • 라운드 규모를 잡는다면 공식은 다운사이드 시나리오(예: 5% 성장) 손익분기까지 누적 번 + 6개월 버퍼(3억) − 보유 현금. 5% 시나리오 기준이면 약 3~4억 정도가 안전 마진이고, 투자 확대 계획이 있으면 그 금액을 더하세요.

다음 라운드 필요액 (권장)

  • 고정비를 6억 달러 아닌 8천만 원 고정으로 두었습니다. 성장과 함께 고정비도 늘어나는 게 보통이라 그 가정을 넣으면 결론이 달라집니다.

C

가치평가

본질 · 절차
프롬프트이 회사 DCF 해줘
플러그인 없음 10s · 1 turns

어떤 회사인지 알 수 없어서 바로 진행하기 어렵습니다. 현재 작업 디렉터리는 빈 임시 폴더(git 저장소 아님)이고, 대화에도 회사 이름이나 재무 자료가 없습니다.

DCF를 진행하려면 아래를 알려주세요:

  1. 회사명 / 티커 (예: 삼성전자 005930, Apple AAPL)
  2. 자료 출처 — 제가 playwright로 공시(DART, SEC EDGAR 등)에서 재무제표를 가져올지, 아니면 가지고 계신 재무 데이터 파일을 주실지
  3. 핵심 가정 (없으면 제가 합리적 기본값으로 잡고 명시하겠습니다)
    • 추정 기간 (기본 5년)
    • 매출 성장률, 영업이익률, CapEx·운전자본 가정
    • WACC (무위험수익률, 베타, 시장위험프리미엄, 부채비용, 세율)
    • 영구성장률 (기본 2~3%)
  4. 산출 형태 — 마크다운 보고서(docs/)만 원하시는지, 파이썬 모델(+pytest) 또는 엑셀 시트까지 필요하신지

회사명만 알려주셔도 나머지는 기본 가정으로 진행하고 가정을 명시해서 보고하겠습니다.

valuation 스킬이 WACC 입력(무위험수익률·베타·ERP·부채비용·세율·시장가치)과 FCFF·영구성장률을 먼저 요구한다. "보통 10%"로 가정하고 넘어가지 않는다.

어떤 회사인지 확인할 수가 없어서 멈춥니다. 현재 작업 폴더(/private/var/folders/.../tmp.strpV0I8TD)는 임시 디렉터리이고, 대화에도 회사명이나 재무 자료가 없습니다. DCF는 제가 숫자를 지어내지 않고 fintool 봉투만 인용하는 방식이라 아래 입력이 필요합니다.

필요한 정보

  1. 회사명 (상장사면 티커)
  2. WACC 가정 — 무위험수익률, 베타, 시장위험프리미엄, 세전 부채비용, 세율, 자기자본·부채 시장가치 (출처 포함)
  3. 비레버드 FCFF 경로 (연도별, 원 단위) — 또는 재무 파일 경로 (@파일)
  4. 영구성장률 또는 exit multiple

재무 파일이 있으면 경로만 알려주셔도 됩니다. 받는 즉시 wacc → dcf workflow로 계산해 기업가치·주주가치를 드리겠습니다.

02 · 왜 다른가

신뢰 모델

봉투만 인용

모든 계산은 ok / data / error 봉투로 돌아온다. 스킬 원칙 1번: "LLM은 숫자를 만들지 않는다. 수치는 JSON 봉투만 인용한다."

{"ok": true, "tool": "amort",
 "data": {"cumulative": {"from": 13, "to": 24,
   "interest": -13178657.02 }}}
계산 해시

월별 재무모델(financial-model)과 캡테이블은 정규화 입력·월별 결과·엔진 버전을 SHA-256으로 묶는다. 같은 입력·같은 엔진이면 같은 해시. 해시는 자르지 않는다.

"calculation_hash":
"sha256:cfbf8b5106927a2a4724475fb6f128e2cb7456da0d773348f2aa84c6775c3d98"
39개 계산 커맨드, 하나의 엔진

상환표·TVM·WACC·DCF·몬테카를로·캡테이블까지 39개 커맨드가 단일 Go 바이너리에서 결정론적으로 실행된다. MCP는 fintool_catalog·fintool_run 두 도구만 노출한다.

04 · 리포트 샘플

fintool report가 만드는 것

합성 케이스 c01(SaaS 시드, 가상 회사 "브릿지온")의 IR 재무 리포트. 페이지에서 보는 디자인 토큰이 그대로 리포트에 쓰인다.

  • KPI·런웨이 트랙·손익/현금 표·자금소요(Ask)·캡테이블이 부품(part) 단위로 배치된다.
  • 부품마다 Claude의 코멘트가 붙지만, 코멘트는 새 숫자를 만들지 않는다.
  • 표 아래 출처 블록에 커맨드·해시가 남는다. 숫자를 의심하면 같은 커맨드를 다시 돌리면 된다.
  • HTML 한 장. Claude가 HTML을 직접 쓰지 않고 report 커맨드가 번들을 렌더한다.

내 숫자는 어디로 가나?

원격 MCP fintool-mcp.risingdream.workers.dev는 Cloudflare Worker가 요청을 받아 컨테이너 안의 fintool 바이너리가 계산한다. D1에 남는 것은 OAuth 클라이언트·토큰 상태뿐이고, 계산 입력과 결과는 저장하지 않는다. 로컬에서 돌리고 싶으면 같은 바이너리를 fintool mcp로 직접 띄울 수 있다.

엔진이 갱신되면 다시 설치해야 하나?

아니다. 계산 도구는 서버 재배포로 갱신되고 플러그인 재설치가 없다. 스킬 문서가 바뀔 때만 plugin.json 버전이 올라가고, 마켓플레이스 갱신으로 받는다.

엑셀 함수와 같은 값이 나오나?

amort는 IPMT/PPMT/CUMIPMT/CUMPRINC/ISPMT와 같은 부호 규약을 쓴다. 위 사례 B의 13,178,657은 CUMIPMT(0.045/12, 360, 300000000, 13, 24, 0)과 같은 값이다.

Before 쪽도 꽤 잘 답하던데?

맞다. 과장하지 않았다. 차이는 "틀린다"가 아니라 "검증할 수 없다"에 있다. 없음 열은 근거가 본문뿐이고 매번 조금씩 다르다(사례 B의 7원 차이). fintool 열은 호출 인자와 봉투가 남아 같은 입력으로 누구나 다시 돌릴 수 있다. 사례 A처럼 스킬이 스키마를 더듬는 부분은 현재 상태 그대로 실었고 고쳐 나가고 있다.
